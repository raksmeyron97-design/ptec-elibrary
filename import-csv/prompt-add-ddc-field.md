# Prompt for Claude Code — add a book-level `ddc` field

Add a Dewey Decimal Classification (`ddc`) field to the physical catalog, end to end.
Right now DDC has nowhere to live, so our PMB migration is being forced into
`shelf_location`, which is wrong: `shelf_location` is a physical shelf/rack code,
DDC is a subject classification.

## Before you write anything

1. Read `CLAUDE.md`.
2. Load the repo's own `admin-form-uxui` skill — every admin form change must follow it.
3. Read these files first; they are the ones that actually define the field set:
   - `lib/catalog.ts` — `CatalogBook`, `CatalogCopy`, `MAX_TEXT`, the `validate*` helpers
   - `lib/catalog-import.ts` — `IMPORT_FIELDS`, `FIELD_DOCS`, `HEADER_ALIASES`, `FIELD_MAX`,
     `NormalizedRow`, `validateRow`, `buildImportGroups`, `buildFailedRowsCsv`,
     `CSV_TEMPLATE_HEADER` / `CSV_TEMPLATE_EXAMPLE`
   - `app/(admin)/admin/(protected)/catalogs/actions.ts` and `import-actions.ts`
   - `app/(admin)/admin/(protected)/catalogs/add/_components/AddBookWizard.tsx`
     and `edit/[id]/_components/EditBookWizard.tsx`
   - `supabase/migrations/0095_catalog_inventory.sql` (where copy-level fields were added)
4. **Produce a plan and stop.** I will approve it before you touch code.

## What I have already verified — do not re-litigate these

- `catalog_copies.call_number` exists (per physical copy, max 80 chars, generated by
  `generateCopies()` as `<base> C.<n>`). It is **not** a bibliographic classification field
  and must keep working exactly as it does today.
- `catalog_books` has **no** classification column at all.
- The CSV import wizard exposes exactly 15 fields and none of them is DDC.
- The live catalog is still empty, so there is no production data to migrate.

## Decisions (already made — implement these, don't ask again)

- `ddc` lives on **`catalog_books`**, not on copies. It describes the work, not the object.
- Type `text null`, max **80** characters — same as the existing `call_number` limit in
  `MAX_TEXT`. (Measured against the real PMB export: only 3 of 13,429 values exceed 80,
  while 55 exceed 32, so 32 would truncate real data.) Real values look like `372.7`,
  `895.922`, `372.7 BIL`, and Khmer local codes like `ស.គ` and `ប.ល`, so:
  - do **not** enforce a numeric-only pattern;
  - trim and collapse whitespace; store `null` when blank.
- Keep `shelf_location` exactly as it is. `ddc` is additive.
- Field order in the CSV import: insert `ddc` **immediately before `shelf_location`**.

## Scope

**1. Database** — new migration, next free number is `0140`.
- `alter table catalog_books add column ddc text` + length check ≤ 32.
- Index it for filtering/sorting (`create index ... on catalog_books (ddc)`); add a prefix
  index too if that is how the existing catalog filters are written — check first.
- Follow the RLS / grant conventions the surrounding migrations use. Do not weaken RLS.
- Do **not** rewrite or renumber any existing migration.

**2. Types & validation** — `lib/catalog.ts`
- Add `ddc: string | null` to `CatalogBook`.
- Add `ddc: 80` to `MAX_TEXT`.
- Add `validateDdc()` next to `validateBarcode()`, same return shape
  (`{ok:true, ddc}` / `{ok:false, error}`).

**3. CSV import** — `lib/catalog-import.ts`
- Add `"ddc"` to `IMPORT_FIELDS` before `"shelf_location"`.
- `FIELD_DOCS` entry: not required, type `text ≤ 80`, example `372.7 BIL`,
  rule explaining it is the Dewey class and that `shelf_location` is the physical shelf.
- `HEADER_ALIASES.ddc`: `["ddc", "dewey", "dewey_decimal", "ddc_number", "classification",
  "class_number", "call_no", "callnumber", "call_number", "លេខរៀបចំ", "ddc_code"]`.
  Careful: `call_number` must map to the **book's** `ddc` here — the import wizard has no
  copy-level call-number field today, so this is not a conflict. Confirm that before adding it.
- Add `ddc` to `FIELD_MAX`, `NormalizedRow`, `validateRow`, the group's book record in
  `buildImportGroups`, and the blank/example CSV templates.
- Add a `FIELD_TOO_LONG` / `INVALID_DDC` issue path consistent with the other fields.
- `buildFailedRowsCsv` picks the header up from `IMPORT_FIELDS`, so verify it still lines up.

**4. Server** — `import-actions.ts` and `actions.ts`
- The server re-validates raw values and must never trust the client: add `ddc` to the same
  normalize+validate path, and to the insert/update payloads.

**5. Admin UI**
- `AddBookWizard.tsx` and `EditBookWizard.tsx`: a `ddc` input in the same step as
  `shelf_location`, with helper text making the distinction obvious
  (DDC = subject class · shelf location = where it physically sits).
- Show `ddc` in the catalog list (`catalogs/page.tsx`) and make the column sortable if the
  other columns there are.
- `StepMapping.tsx` / `StepValidate.tsx` pick fields up from `IMPORT_FIELDS` — verify, don't

**6. Public surface**

- Include `ddc` in catalog search/filter where `category` and `shelf_location` already appear.
- Add it to the catalog CSV export (`lib/export/csv.ts` and its call sites).

**7. i18n** — add every new label/helper/error to **both** `messages/en.json` and
`messages/km.json`. Khmer label: `លេខរៀបចំតាមប្រព័ន្ធ DDC`. No hardcoded user-facing strings.

**8. Tests**
- Extend `lib/catalog-import.test.ts`: header auto-mapping for each alias, validation

  `applyMappings → validateRow → buildImportGroups`.
- Add a `validateDdc` unit test in the `lib/catalog.ts` test file.
- Run `npm run lint`, `npx tsc --noEmit`, and the vitest suite. All must pass.

## Acceptance criteria

- A CSV with a `ddc` column auto-maps at confidence 1.0 with no manual mapping step.
- A CSV **without** a `ddc` column still imports exactly as it does today — no new warnings,
  no behaviour change. This is the regression I care most about.
- `shelf_location` and `catalog_copies.call_number` behave identically to before.
- `ddc` round-trips: import → admin edit → public page → CSV export.
- Zero new TypeScript or lint errors; full test suite green.

## Out of scope

Field first; we will decide on those after real data is in.
