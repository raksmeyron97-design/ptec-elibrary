# SEO OG 4.0 — the Open Graph contract

One builder, one fallback asset, one image rule, for every public page.

Written for: engineers working on `lib/seo/*` or on any public
`generateMetadata`, and whoever runs the post-deploy SEO checks.

---

## 1. Why this exists

Next.js does **not** deep-merge `openGraph`. A page that declares one
**replaces** the object the layout declared, field for field. Nothing errors;
the tags are simply absent, and only a side-by-side diff of two routes shows
it.

A previous pass fixed the whole-object loss with `openGraphBase(locale)` — a
spread of shared defaults. That removed the loss but not the **field-level**
drift, because a spread only supplies what nobody overwrites and a
hand-written block was still free to supply its own. Measured against
production on **2026-09-20**, five shapes were in circulation at once:

| Route | What it emitted |
|---|---|
| `/` | siteName + locale + alternate, image with **no alt** |
| `/about/rules` (and 4 siblings) | siteName + locale, **no alternate**, **no alt** |
| `/about/team/<slug>` | siteName + locale, **no alternate**, portrait with **no alt** |
| `/authors/<slug>` | siteName only — **no locale, no alternate, and no `og:image` at all** when the person has no portrait |
| `/journals/<j>/issues`, `.../issues/<i>` | siteName + image + alt, **no locale, no alternate** |

Plus two image defects of a different kind:

- **Fabricated dimensions.** `lib/seo/book-seo.ts` declared every cover
  `800 × 1200`. Of eight covers sampled from production that day **exactly
  one** was that size; the others were 406×608, 525×601, 800×1034, 922×1200,
  520×691, 800×1164 — and one was **1200×672, landscape, published as a
  portrait**. Facebook and LinkedIn size and crop a card from the declared
  dimensions *before* fetching the bytes.
- **`twitter:card = summary` over a landscape card.** The homepage declared
  `twitter: { title, description }` with no `card`; `twitter` is replaced
  wholesale exactly like `openGraph`, so it overwrote the root layout's
  `summary_large_image`. The site's most-shared URL published its 1200 × 630
  card as a small square crop, on `/` and `/km` alike.

A spread cannot prevent any of this. Only a builder that **owns** the fields
can, and that is what `buildOpenGraph()` is.

---

## 2. The contract

Every indexable public page emits:

```
og:title  og:type  og:url  og:image  og:image:alt
og:site_name  og:locale  og:locale:alternate
```

plus `og:description` **wherever a factual description exists** — a blank one
is omitted, never invented.

- `og:locale` is `en_US` (English) or `km_KH` (Khmer).
- `og:locale:alternate` is the **other** published locale. Every public page
  exists in both (English unprefixed, Khmer under `/km`), so this is a fact
  about the route, not a guess.
- `og:url` **is** `metadata.alternates.canonical` — the caller passes it in.
  This file never reconstructs a URL, because it cannot know whether a listing
  page carries `?page=2`, and reconstruction is how an og:url and a canonical
  come to disagree.

## 3. The builder

`lib/seo/open-graph.ts` — pure, synchronous, takes an explicit `OrgIdentity`
(the pattern `lib/settings-consistency.test.ts` already enforces for every
sync SEO builder).

```ts
openGraph: {
  ...buildOpenGraph({
    locale, org, title, description,
    type: "article" as const,
    url: alternates.canonical,
    image: book.coverUrl,          // optional
    imageAlt: `Book cover: ${title}`,
  }),
  authors, publishedTime, section, tags,   // type-specific fields, spread AFTER
}
```

Spreading the type-specific fields afterwards keeps the `type` literal
discriminating Next's `OpenGraph` union.

`buildTwitter({ card, title, description, images: openGraph.images })` is its
companion. It exists for the same reason and takes the OG images array, so the
two can never name different files. `card` stays the caller's choice —
`/authors/<slug>` and `/about/team/<slug>` legitimately use `summary` for a
portrait.

`og:site_name` comes from the **published** System Settings via
`OrgIdentity.siteName`, never a compiled-in literal.

### What `openGraphBase()` became

It is **gone**. All eleven callers now use `buildOpenGraph()`. Keeping both
would have been a second source of truth, which is the defect this pass
removes.

## 4. The fallback image

`/og-default.png`, **1200 × 630**, generated by
`scripts/generate-og-image.mjs`. Unchanged — there was no evidence the asset
itself was broken, so it was not redesigned.

One constant owns it:

```ts
OG_FALLBACK_IMAGE        // https://library.ptec.edu.kh/og-default.png
OG_FALLBACK_IMAGE_WIDTH  // 1200
OG_FALLBACK_IMAGE_HEIGHT // 630
OG_FALLBACK_IMAGE_TYPE   // "image/png"
```

Seven modules each exported their own `${SITE_URL}/og-default.png`
(`book-seo`, `thesis-seo`, `publication-seo`, `learning-path-seo`,
`journal-seo`, `listing-metadata`, `posts-seo`). All seven now re-export
`OG_FALLBACK_IMAGE`, so existing importers are unchanged and there is one
path, not seven places for a renamed asset to be missed.

`lib/seo/open-graph.test.ts` reads the committed PNG's IHDR header and fails
if its real dimensions stop matching the constants — the constants are a
promise to every crawler, and a regenerated card that changed shape must break
the build rather than let the promise go stale.

## 5. Image selection

```
custom OG override  →  record cover / portrait / journal cover  →  shared card
```

Unchanged in order. Two rules were added:

**The alt describes the image actually used.** `thesis-seo`,
`publication-seo` and `learning-path-seo` each folded the fallback in *before*
computing their alt, so the shared site card was published as
`alt="Thesis cover: <title>"` — a label for an image that is not there.
`buildOpenGraph` ignores `imageAlt` when it falls back and uses the site name.

**Unknown dimensions are omitted, not guessed.** `width`/`height`/`type` are
declared **only** for the fallback, whose size this repository controls. A
record cover, an author portrait and a journal cover get `{ url, alt }` and
nothing else. See §1 for the measurement that motivated this.

**An empty array is not a fallback.** `/catalogs/<slug>` had
`images: ogImage ? [{…}] : []`, and an empty array *replaces* the layout's
default rather than falling through to it — so a record with no cover
published no `og:image`. `buildOpenGraph` always returns exactly one image.

### Books and theses: no dynamic OG image

The brief asked whether the portrait-cover strategy needs a dedicated
1200 × 630 composition. It was **not** implemented, on evidence:

- The measured defect was the **fabricated dimension**, not the cover itself,
  and omitting width/height fixes it at zero runtime cost.
- A generated composition needs dynamic image rendering, which conflicts with
  this project's caching and performance rules ("do not introduce an expensive
  image-generation request on every page view").
- Every cover is a real, factual image of the record. A composition adds no
  information a crawler does not already have.

A portrait cover is cropped to 1.91:1 by Facebook. That is a **known,
documented trade-off**, not a defect — see §10.

## 6. Route categories, after the pass

| Category | Routes | How |
|---|---|---|
| **Specialized builder** | `/books/<slug>`, `/theses/<slug>`, `/journals/articles/<slug>`, `/paths/<slug>`, `/journals/<j>`, `/journals/<j>/issues`, `/journals/<j>/issues/<i>` | `book-seo` · `thesis-seo` · `publication-seo` · `learning-path-seo` · `journal-seo`, each calling `buildOpenGraph` |
| **Shared listing builder** | `/books`, `/theses`, `/theses/summary`, `/posts`, `/catalogs`, `/journals` | `buildListingMetadata` → `buildOpenGraph` |
| **Listing, own builder** | `/paths` | `buildPathsListingMetadata` → `buildOpenGraph` |
| **Route-level** | `/`, `/km`, `/about`, `/about/team`, `/about/team/<slug>`, `/about/committee`, `/about/rules`, `/about/timings`, `/about/collection`, `/about/our-journey`, `/contact`, `/policy`, `/privacy`, `/subjects`, `/subjects/<slug>`, `/authors`, `/authors/<slug>`, `/catalogs/<slug>`, `/posts/<slug>` | `buildOpenGraph` directly |
| **Deliberately excluded** | `/search`, `/books/<slug>/read`, `/dashboard/*`, `/lists/*`, `/offline-books`, `/offline-reader`, all `/admin`, `/auth`, `/api` | `noindex` by design; indexing behaviour untouched |

`lib/seo/open-graph.test.ts` scans both trees and fails if any page or builder
hand-writes an `openGraph` block, hardcodes a site name, writes `en_US`/`km_KH`
by hand, or names `og-default.png` outside this module.

## 7. What was NOT changed

Deliberately, and verified by the untouched tests that pin each:

- canonical URLs and `localeAlternates` (`lib/seo/alternates.ts`)
- hreflang, `x-default`
- every `robots` rule — filtered/out-of-range/empty listings, the subject depth
  gate, composite-author and zero-works `noindex`, `noindex` journals
- `app/sitemap.ts` and `app/robots.ts`
- all JSON-LD
- route URLs, page content, canonical-host logic
- the `og-default.png` asset itself

Two Twitter changes were made, both on measured evidence and both toward the
existing intent rather than away from it:

- `/` and `/km` — `summary` → `summary_large_image`. The page never chose
  `summary`; it declared no `card` at all and the root layout's value was
  replaced. (`/policy`, `/privacy`, `/subjects/<slug>` had explicitly chosen
  `summary` while shipping the landscape card; they follow.)
- `/authors/<slug>` — `summary` when a portrait exists, `summary_large_image`
  when the branded card is served instead. The original rationale was "a
  profile with no photo has nothing to enlarge"; it now has a 1200 × 630 card,
  which `summary` would crop square.

## 8. Tests

`lib/seo/open-graph.test.ts` — 22 tests in four groups:

1. **The contract** — every required field, both locales, reciprocity, og:url
   verbatim including a query string, blank description omitted, site name from
   published settings.
2. **The image hierarchy** — caller's image preferred with the caller's alt;
   no width/height on an unknown image; fallback with its real dimensions; the
   fallback never carries the missing image's alt; an empty string still gets
   the fallback; Twitter points at the same file.
3. **The fallback asset** — the committed PNG's real dimensions match the
   constants; the URL is absolute https on the canonical origin.
4. **Source scans** — no public page or builder hand-writes `openGraph`; no
   literal site name, og locale code or `og-default.png` outside this module.

`lib/seo/validate.ts` gained `validateOpenGraph(og, canonical?)` — the same
structural rules, reusable by the sitemap route and any future admin SEO
report. It checks required fields, og:url ↔ canonical, locale vocabulary and
reciprocity, image presence, alt, absoluteness, and https in production.
`validateSeoMetadata` now delegates to it.

`e2e/seo.spec.ts` — 14 new tests asserting the contract against real rendered
`<head>` on `/`, `/km`, a listing, the authors hub, an author profile, all
eight about/contact pages, the shared card's declared size and its fetchability
without a session, and that a page serving the landscape card asks for
`summary_large_image`.

The existing builder tests were updated to the new (stronger) shape, not
weakened: `twitter.images` now carry `alt` alongside the url, and the fallback
asserts width/height/type.

## 9. Production validation

`scripts/verify-open-graph.ts` — read-only, no database, no fixture list.

```bash
npx tsx scripts/verify-open-graph.ts                      # against production
npx tsx scripts/verify-open-graph.ts --images             # also fetch every og:image
npx tsx scripts/verify-open-graph.ts --base http://localhost:3100
npx tsx scripts/verify-open-graph.ts --json reports/seo/open-graph.json
npx tsx scripts/verify-open-graph.ts --strict             # a manual audit
```

It discovers one live URL per route **shape** from the production sitemap, so
it needs no fixture and cannot go stale as the collection grows. It uses
`lib/verify/http.ts`'s fault vocabulary unchanged: `fail` = the origin answered
and the answer breaks the rule; `unknown` = no answer was obtained, never
counted as a pass *or* a defect; an incomplete run exits 0 with a banner unless
`--strict`. A route shape the sitemap does not advertise is recorded `unknown`,
not skipped silently.

A `noindex` page's breach is `warn`, not `fail` — it is still shareable, so the
check is real, but failing a deploy for it is how a red stops being read.

### Measured

| Run | ok | fail | warn | unknown | sampled |
|---|---|---|---|---|---|
| **Production, before** (2026-09-20) | 149 | **24** | 6 | 0 | 39 URLs |
| **Local production build, after** | 181 | **0** | 0 | 2 | 36 URLs |

The two `unknown` are `/subjects` and `/subjects/<slug>`: the local seed
publishes no subject hub above the depth gate, so no URL of that shape is in
its sitemap. They were verified directly against the same build
(`og:image:alt`, `og:locale:alternate` and `twitter:card` all correct, in both
locales) — the verifier reports them as unverified rather than as passes,
which is the point of the vocabulary.

### After deploying to production

```bash
npx tsx scripts/verify-open-graph.ts --images --json reports/seo/open-graph.json
```

Expect **0 fail**. Then re-scrape the highest-value URLs in the Facebook
Sharing Debugger (`developers.facebook.com/tools/debug/`) — Facebook caches
aggressively and will keep serving the old card until asked.

## 10. Known limitations

- **Portrait covers are cropped by Facebook** to 1.91:1. Deliberate: see §5.
  Revisit only with evidence that share CTR suffers, and only with a cacheable
  build-time composition — never a per-request render.
- **Covers are served as `image/webp`** from Zima Storage. Facebook, LinkedIn
  and Telegram render WebP. X/Twitter's current behaviour with WebP cards is
  **UNKNOWN** here — not measured in this pass.
- **Storage-hosted images are not availability-checked on the request path**,
  by design. `--images` checks them out of band; `file_health` sweeps them
  separately. A cover that 404s in storage yields a card with a broken image,
  and nothing in the metadata path can see that.
- **`/km` alternates are the route's second locale, asserted structurally.**
  If a route ever ships in one locale only, `og:locale:alternate` would claim a
  page that does not exist. No such route exists today; there is no check for
  it.
- **The homepage's Facebook cache** will hold `twitter:card = summary` and the
  alt-less card until a re-scrape. UNKNOWN how long without one.
- **Author portraits**: almost no `authors` row carries `photoUrl`, so nearly
  every author page serves the shared card. That is correct — nothing invents a
  portrait — but it means author shares are not visually distinguishable from
  one another.
