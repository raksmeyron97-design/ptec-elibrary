# បញ្ជីសារពើភ័ណ្ឌទិន្នន័យឯកជនភាព (Privacy Data Inventory)

_បញ្ជីសារពើភ័ណ្ឌសម្រាប់អ្នកអភិវឌ្ឍន៍ដែលគាំទ្រទំព័រឯកជនភាពសាធារណៈ `/privacy`។ បានបង្កើតនៅថ្ងៃទី ២៥ ខែកក្កដា ឆ្នាំ២០២៦។ ត្រូវរក្សាឱ្យស្របគ្នានឹង `docs/DATA-GOVERNANCE.md`, namespace `privacy` នៅក្នុង `messages/{en,km}.json` និងកូដអនុវត្តដែលបានបញ្ជាក់ខាងក្រោម។ ផ្អែកតាម DATA-GOVERNANCE §7 រាល់ការផ្លាស់ប្តូរចំពោះអ្វីដែលគេហទំព័រប្រមូល រក្សាទុក ឬបង្ហាញ ត្រូវតែបច្ចុប្បន្នភាពឯកសារនេះ អត្ថបទឯកជនភាពសាធារណៈ និងកូដអនុវត្តក្នុងការផ្លាស់ប្តូរតែមួយ (in the same change)។_

ឯកសារនេះគឺជាប្រភពពិត (source of truth) សម្រាប់អ្វីដែលកម្មវិធីប្រមូលប្រាកដប្រជា ដែលបានផ្ទៀងផ្ទាត់ដោយការអាន schema, server actions, API routes, និង middleware — មិនមែនដោយការអានអត្ថបទគោលការណ៍ចាស់ឡើយ។ ទំព័រសាធារណៈមិនត្រូវអះអាងលើស ឬខ្វះជាងអ្វីដែលបានចុះបញ្ជីនៅទីនេះឡើយ។

## 3. ចំណុចខុសគ្នារវាងការអនុវត្តជាក់ស្តែង និងអត្ថបទគោលការណ៍ចាស់ (Discrepancies found vs. previous policy)

អត្ថបទ `/privacy` ចាស់មានភាពត្រឹមត្រូវតាមអ្វីដែលវាបានបញ្ជាក់ ប៉ុន្តែ**មិនបានបញ្ជាក់ឱ្យអស់**។ ចំណុចខ្វះខាតដែលត្រូវបានកែសម្រួលក្នុងទំព័រថ្មី៖

1. **Vercel Analytics** មិនត្រូវបានលើកឡើងឡើយ។ វាត្រូវបានផ្ទុកនៅក្នុង `RootShell.tsx`។ ឥឡូវនេះត្រូវបានបញ្ជាក់ថាជាការវិភាគសរុបរួម និងមិនប្រើ cookie។
2. **ប្រវត្តិរូបសម្រាប់សិទ្ធិទាញយក (Download Access Profile)** (ភេទ, ទូរស័ព្ទ, ស្ថាប័ន, តួនាទី, គោលបំណង — migration 0093) មិនត្រូវបានលើកឡើងទាល់តែសោះ។ ឥឡូវនេះត្រូវបានបញ្ជាក់ (ថ្នាក់ទី ២)។
3. **ការจัดการអាសយដ្ឋាន IP** មិនត្រូវបានបញ្ជាក់ឡើយ។ វាត្រូវបានរក្សាទុកលើសារទំនាក់ទំនង និងប្រើសម្រាប់កម្រិតអត្រាប្រើប្រាស់; កំណត់ត្រាស្វែងរកត្រូវបានរក្សាទុកដោយចេតនានូវ HMAC session hash មិនមែន IP ដើមឡើយ។ ឥឡូវនេះត្រូវបានបញ្ជាក់ និងបែងចែកច្បាស់លាស់។
4. **ការចុះឈ្មោះ Push**, **Cloudflare Turnstile**, និង **ការដំណើរការអត្ថបទស្វែងរកដោយ Gemini AI** មិនត្រូវបានបញ្ជាក់ឡើយ។ ឥឡូវនេះត្រូវបានបញ្ជាក់ច្បាស់លាស់។
5. **"បុគ្គលិកបណ្ណាល័យមិនអាចមើលពួកវាបានទេ"** ជាការថ្លែងលើសពីความเป็นจริงនៃឯកជនភាព។ ត្រូវបានកែតម្រូវទៅជា៖ ទិន្នន័យឯកជនមិនត្រូវបានបង្ហាញក្នុងផ្ទាំង Admin ទេ ប៉ុន្តែអ្នកគ្រប់គ្រងបច្ចេកទេស (technical steward) មានសិទ្ធិចូលប្រើ database ក្រោមការត្រួតពិនិត្យសិទ្ធិ (DATA-GOVERNANCE §6)។ ត្រឹមត្រូវតាមទិដ្ឋភាពជាក់ស្តែងនៃ RLS + service-role។
6. **រយៈពេលរក្សាទុក (Retention)** ត្រូវបានរៀបរាប់ត្រឹមតែ "កំឡុងពេលគណនីរបស់អ្នកមាន"។ ឥឡូវនេះផ្តល់រយៈពេលតាមថ្នាក់ទិន្នន័យ (ស្វែងរក ៣៦៥ ថ្ងៃ, កំណត់ត្រាទាញយក/មើលដើម ១ ឆ្នាំ, ទំនាក់ទំនង ២ ឆ្នាំ, សវនកម្ម ≥ ២ ឆ្នាំ) ស្របតាម DATA-GOVERNANCE §2។
7. **ការលើកលែងចំពោះការលុប (Deletion exceptions)** មិនត្រូវបានបញ្ជាក់ឡើយ។ ជួរទិន្នន័យសវនកម្ម Admin សម្រាប់សកម្មភាពបុគ្គលិក និងខ្សែសន្ទនាទំនាក់ទំនងត្រូវបានរក្សាទុក; Backups នឹងអនុវត្តការលុបក្នុងរង្វង់ ~៦ ខែ។ ឥឡូវនេះត្រូវបានបញ្ជាក់ច្បាស់ (DATA-GOVERNANCE §3)។
8. **"គ្រប់ការភ្ជាប់ប្រើប្រាស់ការស៊ើបការណ៍ HTTPS"** ប្រឈមនឹងការយល់ច្រឡំថាមានការស៊ើបការណ៍ពេលរក្សាទុក (at-rest encryption)។ ត្រូវបានសរសេរឡើងវិញដើម្បីបំបែករវាងទិន្នន័យកំពុងធ្វើដំណើរ (HTTPS/TLS), ទិន្នន័យពេលរក្សាទុក (ការរក្សាទុកគ្រប់គ្រងដោយ Supabase), និងការត្រួតពិនិត្យសិទ្ធិចូលប្រើ (RLS + ការផ្ទៀងផ្ទាត់សិទ្ធិខាង server) — តាមតម្រូវការ។
9. **ឆានែលបណ្តឹងតវ៉ា** ធ្លាប់មានន័យប្រយោល។ ឥឡូវនេះមានភាពច្បាស់លាស់ (ទម្រង់ទំនាក់ទំនង / អ៊ីមែល; ការឆ្លើយតបក្នុងរយៈពេល ៣០ ថ្ងៃតាម DATA-GOVERNANCE §4)។

## 4. អ្វីដែលមិនត្រូវបានប្រមូល (បានផ្ទៀងផ្ទាត់)

- គ្មានពាណិជ្ជកម្ម, គ្មានបណ្តាញពាណិជ្ជកម្ម, គ្មាន tracking pixels ឆ្លងកាត់គេហទំព័រ (cross-site)។
- គ្មានការលក់ទិន្នន័យផ្ទាល់ខ្លួន។
- គ្មានឧបករណ៍តាមដានឥរិយាបថភាគីទីបី (មានត្រឹមតែការវិភាគសរុបរួម Vercel ដែលមិនប្រើ cookie)។
- គ្មានទិន្នន័យការទូទាត់ (បណ្ណាល័យនេះឥតគិតថ្លៃ; គ្មានតារាង premium/payment ឡើយ)។
- គ្មានការភ្ជាប់ Telegram សម្រាប់ទិន្នន័យអ្នកប្រើប្រាស់ (Telegram បង្ហាញត្រឹមតែជាតំណបណ្តាញសង្គមក្នុង settings ប៉ុណ្ណោះ មិនមែនជាឆានែលទិន្នន័យទេ)។
- កំណត់ត្រាស្វែងរក**មិនរក្សាទុក IP ដើមឡើយ** — ត្រឹមតែ HMAC session hash ប៉ុណ្ណោះ។
